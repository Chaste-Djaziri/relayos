# Changelog

All notable RelayOS changes are recorded here. Entries under **Unreleased** are applied to the local development branch, not necessarily the installed app.

## Unreleased

Preserve the physical camera exclusion as unoccupied black space; add six geometry/phase tests and three local #Previews. No production app deployment.
- Replace the oversized notch control panel with a compact, physical-notch-aware black build monitor. Left/right ears occupy only the measured menu-bar side regions, the center remains transparent, and a lower tray opens live Terminal Jobs. Includes in-file previews and display geometry tests; installed app remains unchanged.
- Make terminal jobs observable throughout the macOS app lifecycle: authenticated local job-list/cancel endpoints, compatibility fallback for older hybrid bundles, live output following with byte offsets and command-reported progress, optional completion notifications, job counts in the menu bar/notch/sidebar, and UTF-8-safe incremental output. Python backend retained and live installed app unchanged.
- Rebuilt the menu-bar RelayOS control center with status-first cards, an approvals shortcut, connected-client summary and confirmed service actions; added an optional theme-aware top-center notch companion, macOS Controls menu shortcuts, and a compact Settings toolbar. The Python-backed production runtime is retained; the installed app is unchanged.
- Implement native development-only OAuth authorization-code/PKCE, refresh rotation and revocation, locally approved file writes/patches, safe asynchronous command jobs and native screen capture/guidance overlays. Approval inbox shows pending requests; Python code and installed production remain untouched. Full public MCP transport parity remains pending.
- Add isolated Swift-only Xcode Debug mode (`RELAYOS_SWIFT_ONLY=1`) with in-app loopback MCP on port 18765, native system/process/project read tools, owner-only test credentials, folder consent through NSOpenPanel and verified no-Python startup path. Production Python backend remains unchanged until OAuth, approval, command/job and screen parity.
- Xcode Command+R now launches the actual RelayOS Settings UI with live model/configuration, instead of BridgeModel.preview(); development mode monitors but never owns or restarts the installed MCP/ngrok services. SwiftUI #Preview blocks remain mock-data only.
- Begin native single-process Swift MCP migration: experimental loopback-only Network.framework listener, native SQLite authorization checks compatible with existing OAuth/session state, and three read-only MCP tools. Production Python service remains active until security and OAuth parity.
- Replace separate Xcode preview showcase with local `#Preview` declarations alongside each native screen, setup step, reusable settings component, terminal row and permission guide. The Xcode Debug app now renders the real Settings window with inert sample state; no MCP/ngrok starts.
- Align Xcode Release and packaged macOS bundle identity to `pro.micorp.relayos`, use `pro.micorp.relayos.dev` for isolated Debug, and configure RelayOS name, Utilities category, version 1.0.0, build 1 while preserving user-customized Xcode project and schemes.
- Added an Xcode-managed macOS app project with a dedicated safe Debug UI preview scheme, distinct .dev bundle identity, automatic code-signing controls, shared existing SwiftUI sources, and native test target; the production Python MCP deployment remains unchanged.
- Documented Xcode signing and distribution workflows plus a staged, authorization-preserving migration roadmap for replacing Python with native Swift services.
- Window-first W01: keep RelayOS running when the Settings window closes; move managed-process termination waits and emergency-stop confirmation off the UI thread; avoid terminating unowned ngrok processes. Added constrained configured-endpoint HTTP 401 verification when ngrok's local inspector is unavailable, with regression tests.
- Window-first W02: replace heuristic macOS privilege badges with honest permission observations and a separate floating permission guide with an optional draggable signed-app icon, Finder fallback, privacy-pane navigation, and refresh after returning to the app.
- Window-first W03: confirm folder-permission revocations, run them off the UI thread, keep the ngrok tunnel alive when saving tool settings, identify stored OAuth grants as authorizations, and extend sidebar keyword search and motion/accessibility behavior.
- Window-first W04/W05: native four-step onboarding with inert product previews and optional-permission setup; added safe light/dark component preview fixtures and window lifecycle/permission tests.
- Dedicated Appearance page with System/Light/Dark visual mode previews, saved accent selection, UI font-size control, and advanced motion/sidebar preferences; window and menu bar share theme selection.
- UI modernization: reorganized native settings navigation into Workspace, Connections & tools, and Privacy, added a dedicated RelayOS sidebar identity and wider settings canvas, and introduced persisted System/Light/Dark appearance selection. Native Swift tests pass. This work remains unreleased.
- Sprint 04 macOS: added native Terminal Jobs view with live metadata polling, bounded incremental stdout/stderr display, cancellation controls, and search by executable/project/status. All native output fetches use the authenticated loopback control token; new model-decoding tests verify job state and offsets.
- Sprint 04 backend: added opt-in approved background command jobs (no shell), session-bound list/read/cancel MCP tools, bounded 8 KiB incremental stdout/stderr reads, metadata-only local SQLite job history, emergency-stop/timeout/output-limit cancellation, and isolated local control output access. Job output is temporary in the owning MCP process; on restart previous in-progress metadata is marked interrupted. Added regression coverage (116 Python tests passed; one pre-existing Pydantic warning).
- Expanded persisted metadata-only auditing to capture approval creation and expiration, and to attribute OAuth decisions to a registered client name without logging raw command arguments, callback URIs or tokens. Added privacy and expiry regression coverage (109 Python tests passed).
- Added native Approval Center with nonblocking multi-request inbox, explicit local Once/Session/Always/Deny actions (OAuth limited to Approve/Deny), searchable persisted audit history, menu bar pending count, and optional privacy-preserving macOS notifications. Deduplicated arrival sounds/notifications across repeated polls and added Swift decoding/arrival tests. Corrected development-only working-directory assumption for permission grants.
- Added a local-only unified approval inbox and searchable persisted metadata-only activity feed, routing command/project decisions and OAuth connection approval through fail-closed SQLite authorization. Added stale/expired, emergency-stop and independent queued-request regression tests (107 Python tests passed).
- Added an isolated packaged MCP crash/restart smoke test (ephemeral loopback port and temporary state) and a native real-child process-slot test to ensure old termination callbacks cannot discard replacements.
- Hardened native single-instance coordination with a stable, user-owned, non-symlink flock lease and tested contention/release plus rejection of insecure lock files. The takeover path still requests graceful retirement of the old app rather than killing unrelated processes.
- Integrated authenticated periodic public tunnel checks with bounded retry/recycle of only app-owned MCP/ngrok children after repeated failures, stale-probe generation guards, and accurate local/public health labels in the menu and Settings. Removed ngrok stdout-based URL adoption and one-shot inspector discovery.
- Added an ngrok tunnel probe that validates inspector forwarding to the RelayOS loopback MCP port and checks that the public MCP route returns the expected unauthenticated HTTP 401 (not a tunnel 404); includes strict ownership/URL parsing and isolated Swift tests.
- Redesigned the native Command Permissions view into expandable project/executable groups instead of repetitive full-height rows, with privacy-preserving exact-scope fingerprints, saved-approval counts and an explicitly confirmed Remove duplicates action. Kept per-grant revocation available.
- Approval dialogs now identify the requested command rather than the internal `project_command` kind, and clearly distinguish a reusable prefix from an exact-command grant. The saved Command Permissions view is also embedded directly in Tools & permissions so users can find and revoke approvals without locating a separate tab.
- Added a native Command Permissions screen with searchable project-scoped grants, visible command prefixes, approved executable, working directory, duration/expiration, refresh, and confirmation-based revocation. Changing a grant's scope requires revocation and fresh local approval. Added Swift presentation-model tests.
- Added native-helper commands for reading and revoking saved command approvals, with local CLI tests.
- Native approval dialogs now show the requested immutable command prefix versus the variable argument suffix. New command and MCP connection approval requests play a short macOS sound by default; the new General → Approval notifications setting lets users disable it. Added sound-preference regression coverage (16 Swift tests passing).
- Added client-proposed, locally approved literal `scope_prefix` for repeatable project commands (for example `git commit`, `npm install`, or `npm run build`). Reusable prefixes are constrained to the resolved executable, authorized project, working directory, local duration and immutable leading argv tokens. Once remains exact; arbitrary shells/interpreters do not support reusable prefixes. Added approval-tampering, session, revocation and database-reopen regression tests (96 Python tests passing).
- Added `scripts/smoke_packaged_mcp.py` to start the signed bundle's MCP helper with isolated temporary state and an ephemeral loopback port, verify anonymous rejection and authenticated status, and safely terminate only the test subprocess.
- Added an opt-in native integration test (`RELAYOS_TEST_LIVE_MCP=1`) that checks the authenticated loopback health endpoint without modifying or restarting the live MCP service.
- Added a native `ServiceSupervisor` with bounded server/tunnel crash-retry delays, non-overlapping authenticated health probes, safe handling of stale probes during restarts, and recovery tests. The app no longer trusts an occupied MCP port without authenticating the control response, and starts the tunnel only after healthy verification.
- Added a loopback-only authenticated MCP health monitor for the native supervisor. It validates the local token file, verifies the RelayOS control-response contract and distinguishes connection failures from unauthorized or unexpected listeners. Added four Swift health-probe tests.
- The macOS command-approval dialog now explains one-time versus reusable scope, highlights **Once** by default, and labels allowlisted family permissions explicitly (for example, **Always allow git add**).
- Updated the macOS implementation roadmap with completed Phase 01 milestones, test results, and the remaining deployment/ownership acceptance checks.
- Development Python helpers are now located through validated repository discovery (or `RELAYOS_DEV_ROOT`) instead of a hardcoded home-directory path; installed builds still prefer their bundled helpers.
- Moved the observable service/approval model and local Keychain helpers out of the app entry point into `RelayOSRuntimeModel.swift`, leaving `RelayOSApp.swift` responsible for application composition only.
- Split the menu-bar panel, onboarding, desktop window, and settings SwiftUI screens into `RelayOSViews.swift`; the app entry point now focuses on state and services.

### Fixed
- Saved project-command approvals are now idempotent for the same exact scope; added a local-only duplicate preview/cleanup that retains the newest grant per precise project, executable, cwd, duration, session and command scope. Legacy exact grants now expose a short non-reversible scope fingerprint for display without storing raw argument strings. Added focused regression tests.
- Automatically suggest narrow locally approved reusable scopes for common Git, npm/pnpm/yarn, Swift, Cargo, and Go command forms when MCP clients omit `scope_prefix`; `git commit -m` now remembers the `git commit` prefix after Always allow instead of exact commit messages. Unknown or shell/interpreter commands remain exact unless explicitly scoped and locally approved. Added regression tests.
- Hardened saved-prefix evaluation to reject malformed/null prefix records rather than interpreting them as wildcard command access; added regression coverage (97 Python tests passing).
- Ignore stale MCP health responses after a managed server crash, preventing a response from the dead process from resetting restart cooldown or marking the new server healthy. Added a crash-generation regression test.
- Pre-create the authenticated loopback control token before binding the Python MCP listener so fresh native installations can verify the server without an unauthenticated bootstrap request. Added a startup-order regression test.
- Fixed the SQLite startup migration incorrectly revoking new `git add` family grants on each approval-helper process launch. Recognized scoped family grants now survive database reinitialization while legacy executable-wide permissions remain revoked; added a fresh-process regression test.
- Approval duration now follows the local person's Once/Session/Always decision, even when the MCP client requested once. Reusable `git add` grants cover varying file arguments only within the same project, working directory, and resolved Git executable; session grants expire with the originating coding session, while unrelated Git commands remain separately authorized. Added regression tests.
- Child server/ngrok exits now clear their process slot only when it still owns that specific process; restarts wait for owned subprocesses to exit, and failed launches no longer leave stale process references. Includes a regression test for delayed termination callbacks.
- macOS startup now waits for exclusive single-instance ownership before starting the MCP helper, ngrok, or approval polling. Added a native regression test for pre-lock startup.
